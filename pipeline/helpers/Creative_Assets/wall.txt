The **SideWall asset** is constructed as a parametric vertical architectural element that simulates a brick-textured wall using a combination of a rounded rectangular base and procedurally generated horizontal line segments. The entire structure is centered at the origin by default, with all internal geometry built relative to this center. The wall’s primary dimensions are controlled by two parameters: `h_wall = 4.7`, which defines the total vertical height of the wall, and `width = 0.8`, which is fixed within the construction logic. This creates a tall, narrow rectangular profile with an aspect ratio of approximately 5.9:1 (height to width), giving the wall a pillar-like appearance.

The foundational geometry is established using a `RoundedRectangle` (Manim mnemonic: `RoundedRectangle(width, height, corner_radius)`), where the width is set to `0.8` units and the height is dynamically set to `h_wall`. The corner radius is fixed at `0.2`, introducing a subtle curvature at all four corners, which softens the otherwise rigid rectangular form. This rectangle is filled (`fill_opacity = 1`) with a base brick color `#8B3A3A` and has no visible stroke (`stroke_width = 0`), making it a solid visual block. Since the rectangle is centered, its top and bottom edges lie at `+h_wall/2` and `-h_wall/2` along the Y-axis, respectively, while its left and right edges lie at `-0.4` and `+0.4` along the X-axis.

Overlaying this base are the **horizontal brick lines**, constructed as a `VGroup` of `Line` objects that span the full width of the rectangle. These lines are generated procedurally based on the parameter `num_lines = 11`, which determines how many horizontal segments are drawn. Before placement, a **usable vertical region** is defined as `usable_h = h_wall - 0.4`. This introduces a vertical margin of `0.2` units at both the top and bottom (total margin = 0.4), ensuring that the lines do not touch the rounded edges of the rectangle. For a default height of `4.7`, this results in `usable_h = 4.3` units.

The spacing between lines is calculated as `spacing = usable_h / (num_lines - 1)`, which for 11 lines yields a spacing of `4.3 / 10 = 0.43` units. Each line is then positioned using a loop over `i = 0 to 10`, where the vertical offset for each line is computed as
`y_offset = -usable_h/2 + (i × spacing)`
This means the first line (i = 0) is placed at `-2.15` units, and the last line (i = 10) is placed at `+2.15` units along the Y-axis, creating a perfectly symmetric distribution around the center. Each line is constructed using the endpoints:
`start = rect.get_left() + UP × y_offset` and
`end = rect.get_right() + UP × y_offset`
(Manim mnemonic: `Line(start, end)`). Since `rect.get_left()` and `rect.get_right()` correspond to `(-0.4, 0, 0)` and `(0.4, 0, 0)` respectively, each line spans the full width of `0.8` units and is horizontally aligned. The lines are styled with a darker brick tone (`#5C2626`) and a stroke width of `3`, making them visually prominent against the base.

All components—the rounded rectangle and the collection of lines—are combined using the `become(VGroup(...))` pattern. This is a critical construction detail: instead of modifying individual subcomponents, the entire structure is rebuilt and replaced in-place using `self.become(...)`. This ensures that the object retains its identity (important for external references in a RAG workflow) while allowing complete geometric redefinition. This pattern is especially useful for dynamic parameter updates such as height and line density.

The asset exposes **parametric mutators** that directly influence its construction. The `set_height(h)` method updates `self.h_wall` and triggers a full rebuild via `redraw()`, causing both the base rectangle and all line positions to be recalculated based on the new height. Similarly, `set_num_lines(n)` updates the number of horizontal divisions and recomputes spacing accordingly. The `get_height()` method provides access to the current height value, enabling external systems to query the asset’s geometry. These setters ensure that the wall can be dynamically resized or retextured while preserving structural consistency.

Finally, the asset includes a **behavioral helper** method `bump_animation()`, which returns a `Succession` animation that shifts the entire wall slightly to the right by `0.1` units and then back to the left by `0.1` units (Manim mnemonic: `self.animate.shift(RIGHT * 0.1)` followed by `LEFT * 0.1`). While this does not alter the construction, it provides a reusable motion primitive for subtle emphasis. Overall, the SideWall asset is a procedurally defined structure where all visual elements are derived from a small set of parameters and positioned using precise arithmetic relationships, making it highly adaptable and consistent within larger architectural compositions.
