The **WindowSystem asset** is constructed as a layered composite structure that simulates a realistic window view by organizing three tightly coordinated subsystems: the background environment, the structural window frame, and interior foreground props. The entire composition is anchored to a central reference coordinate `center_point`, and all spatial elements are positioned relative to this point. The primary bounding box of the window is defined by `width = 2.8` (ww) and `height = 3.6` (wh), which act as the core dimensions for both the visible glass area and the alignment of all surrounding elements. The layering is explicitly controlled using `z_index`, ensuring a strict rendering order: environment (z=0), frame (z=2), and plant (z=3).

The **environment layer** begins with a base sky rectangle constructed using `Rectangle(width = ww + 1, height = wh + 1)` and positioned using `move_to(center_point)`. This results in a background canvas of size `3.8 × 4.6`, extending `0.5` units beyond the window frame on all sides, ensuring complete coverage behind the structure. This sky acts as a color-interpolated base for time-of-day transitions. In front of the sky, a procedurally generated **cityscape** is constructed using a predefined dataset of building parameters `(width, height, x_offset, color)`. Each building is created as a `Rectangle` and positioned using
`move_to(center_point + [x_offset, -wh/2 + height/2, 0])`.
This ensures that every building sits flush on the bottom edge of the window view, since `-wh/2` corresponds to the bottom boundary of the window, and adding `height/2` vertically centers each building on that baseline. For example, a building of height `2.2` is positioned at `y = -1.8 + 1.1 = -0.7`. Horizontally, buildings are distributed using offsets ranging from `-1.2` to `+1.4`, spanning nearly the full width of the visible scene.

Each building is populated with **window lights**, generated through a nested grid logic. The number of rows and columns is computed as `rows = int(height / 0.25)` and `cols = int(width / 0.2)`, creating a dense grid of potential light positions. For each grid cell, a small rectangle (`0.06 × 0.1`) is placed using coordinates derived from the building’s bottom-left corner:
`x = building_left + c × (width / cols)` and
`y = building_bottom + r × (height / rows)`.
Only a subset of these cells (≈65%) are instantiated based on a random threshold (`np.random.random() > 0.35`), and their initial opacity is set to `0`, allowing them to be activated later via updaters.

The **celestial elements** are positioned within the same coordinate system. The sun is constructed as a `VGroup` of two concentric circles (radii `0.45` and `0.3`) centered initially at the origin, while the moon is a single `Circle` of radius `0.25`. Their positions are later controlled dynamically, but structurally they are centered and scaled to remain proportionate within the window. The **stars** are distributed randomly across a rectangular region defined by `x ∈ [-1.5, 1.5]` and `y ∈ [-2.0, 2.0]`, relative to `center_point`. Each star is a `Dot` with radius randomly sampled between `0.015` and `0.035`, and all stars are initialized with `opacity = 0`, effectively hidden until activated.

The **clouds** are constructed using a helper function that assembles five overlapping circles into a single organic shape. Each circle is positioned relative to the cloud’s local center using shifts such as `LEFT * 0.3`, `UP * 0.1`, `RIGHT * 0.35 + DOWN * 0.05`, etc. (Manim mnemonic: `shift(direction_vector)`). This creates an asymmetric, fluffy structure. Two such clouds are instantiated: one scaled to `0.8` and positioned at `center_point + UP * 1.2 + LEFT * 0.5`, and another scaled to `0.6` at `center_point + UP * 0.3 + RIGHT * 1.0`. These placements ensure vertical layering within the sky and horizontal spread across the window.

The **frame layer** defines the physical structure of the window. The outer frame is a `Rectangle(width = ww + 0.2, height = wh + 0.2)` = `3.0 × 3.8`, positioned at `center_point`, creating a border thickness of `0.1` units around the glass. Inside it sits the **glass pane**, a `Rectangle(width = ww, height = wh)` = `2.8 × 3.6`, perfectly aligned using `move_to(center_point)`. The glass is subdivided into four quadrants using two `Line` objects: one vertical line from `glass.get_top()` to `glass.get_bottom()`, and one horizontal line from `glass.get_left()` to `glass.get_right()`. These lines intersect at the center, forming a cross-divider with stroke width `6`.

Below the frame sits the **window sill**, constructed as a `Rectangle(width = ww + 0.6, height = 0.15)` = `3.4 × 0.15`. It is positioned using `next_to(outer_frame, DOWN, buff = -0.05)`, which places it directly beneath the frame with a slight overlap of `0.05` units upward. This ensures visual continuity between the frame and sill. The sill’s vertical position is therefore approximately `center_y - (wh/2 + 0.1 - 0.05)`, accounting for frame thickness and overlap.

The **interior plant** is constructed as a foreground prop and positioned relative to the sill. The base is a `Polygon` defined by four points: `[-0.15, 0, 0]`, `[0.15, 0, 0]`, `[0.1, -0.35, 0]`, and `[-0.1, -0.35, 0]`, forming a trapezoidal pot of width `0.3` at the top and narrowing to `0.2` at the bottom, with height `0.35`. Above this pot, three `Ellipse` objects are arranged as leaves. Each ellipse is rotated (`rotate(angle)`), positioned using `next_to(pot, UP, buff = negative_value)` to slightly overlap the pot, and then shifted horizontally (`shift(LEFT * 0.1)` or `RIGHT * 0.1`) to create asymmetry. For example, one leaf is rotated by `-π/4` and shifted left by `0.1`, while another is rotated by `π/4` and shifted right. The third leaf is rotated by approximately `π/2.2` and centered. The entire plant group is then positioned using
`next_to(self.sill, UP, buff = 0)` followed by `shift(RIGHT * 0.9)`, placing it directly on top of the sill and offset `0.9` units to the right from the window center.

All three layers—environment, frame, and plant—are combined using `self.add(env, frame, plant)`, preserving their z-index hierarchy. The asset exposes **getter methods** such as `get_sill()` and `get_plant()` to allow external alignment or interaction with specific subcomponents. Additionally, a suite of **updater factory methods** is defined to enable dynamic behavior without altering the static construction. These include `get_sky_updater` (color interpolation using `interpolate_color` and `np.sin`), `get_lights_updater` (opacity modulation based on sine wave), `get_orbit_updater` (circular motion using `cos` and `sin` around a pivot with radius `2.4`), `get_stars_updater`, `get_day_fade_updater`, and `get_cloud_motion_updater`, which implements horizontal motion using `mob.shift(RIGHT * 0.3 * dt)` with wrap-around logic between `x = center_x ± 1.4`. These helpers operate on the pre-constructed geometry, enabling temporal simulation while preserving the integrity of the underlying structure.

Overall, the WindowSystem asset is a meticulously layered construct where each component is positioned using explicit numerical offsets relative to a central coordinate system. The use of proportional scaling, trigonometric placement, and hierarchical grouping ensures that the scene remains visually coherent while supporting complex dynamic behavior through external control.
